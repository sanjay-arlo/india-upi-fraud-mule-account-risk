# India UPI Fraud & Mule-Account Risk Analysis

> Business Analyst portfolio case study analysing transaction-level risk signals to prioritise fraud-review workload and mule-account investigation.

## 🚀 Live Dashboard

**[Open the interactive dashboard](https://sanjay-arlo.github.io/india-upi-fraud-mule-account-risk/)**

## Business question

**Which fraud signals create the highest review risk, and how should investigators prioritise limited fraud-operations capacity?**

## Dashboard

Explore case severity, loss exposure, signal frequency, recovery-window compliance and risk-ranked investigation queues.

## KPI logic

**Risk score** combines transaction anomalies, account behaviour and case indicators into a transparent portfolio score.

**Recovery-window compliance** = cases recovered within defined review window / eligible cases × 100.

## Dataset

Synthetic/illustrative fraud-signal records are used for portfolio demonstration. They are not official RBI, NPCI, bank or law-enforcement data.

## Production upgrade

Integrate governed transaction telemetry, device/account/network signals, confirmed fraud outcomes and investigation feedback loops. Add model validation, explainability, access controls, audit logs and privacy-by-design controls.

## Safety and limitation

This project is for analytics portfolio demonstration. Risk scores must not be treated as proof of fraud, and operational decisions require validated models and authorised review processes.
